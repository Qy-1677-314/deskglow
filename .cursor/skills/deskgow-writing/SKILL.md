# DeskGlow：书面说明

读者能看到的中文按这一页写。包括 README、`docs/`、发布说明、提交说明、PR 标题和正文、仓库简介。源码标识符、界面上已经存在的按钮名称、注册表路径和快捷键保持原样。不要为了统一措辞去改源码注释，也不要改冻结的窗口层级说明里的技术结论。

版本号怎么出现，以 `.cursor/skills/deskgow-release/SKILL.md` 为准。本文只管措辞。

## 语体

用书面陈述句。一句里先写能力或结果，再写入口、范围和限制。

- 主语用「用户」「程序」「接收方」，或写成无主语句。不用「你」「对方」「咱们」。
- 标题和表格第一列写能力名称，用名词短语。不写口号，不写评价。
- 同一概念只用一个名称：文件收纳、控制面板、小组件、元素、预设、软件文件夹。测试记录里如果当时的界面叫「文件合集」，保留该名称，并让读者知道它是当时的叫法。
- 界面字符串用「」括起，与正文区分，例如「添加元素」。
- 不使用感叹号。不写「一键」「随便」「搞定」「秒开」「瞄得准」「像手机一样」。
- 程度写可以核对的说法：写「约 2–5 秒」，不写「很快」。

## 版式

- 中文与英文、数字之间留一个空格：`Electron 33`、`128 像素`、`Win + D`。反引号内的代码、路径、命令不插入空格。
- 句子使用中文标点。并列的词语用顿号，两项之间也可以用「和」「或」。
- 单位写成中文或国际符号并与数字隔开：`16–96 像素`、`8 MB`、`0.6 秒`。范围用半角连接号 `–`。
- 操作顺序用「→」，两侧各留一个空格：「关于 → 退出」。
- 同一列表里的句子结构保持一致：都用名词短语，或都用完整陈述句。

## 仓库简介、提交说明、PR

- 仓库简介一句说完：对象、平台、做什么。不用加号把功能串成口号。
- 提交说明用一两句陈述这次改动的原因或结果。不写「发布 x.y.z」。
- 发版 PR 的正文第一行是 `## x.y.z`，下面直接列用户可见的变化。需要展开时再分小节，最后是 `### Test plan`。测试项写成可以执行的检查。
- 其他 PR 用「摘要」列出变化，同样以 `### Test plan` 结束。

## 例子

口语：五种元素，随便加。时钟 / 日期 / 电量，下拉点一下即可。

书面：五种元素。提供时钟、日期、电量和文本，每种均可重复添加。入口为「添加元素」。

口语：做完还能打包成分享给别人，对方导入就能用。

书面：编排完成后，可将全部元素导出为预设文件，供其他计算机导入。

口语：版本号改为 1.1.1，接在上一版之后。充电时马上出闪电。

书面：正文以 `## 1.1.1` 起头，下一条写「电池处于充电状态时，图标显示黄色闪电。」

## 改完看一遍

读者能在 GitHub 上读到的段落里，不应再出现「你」「随便」「一键」「对方」「秒开」。中文和紧挨着的英文或数字之间应有空格。按钮和菜单名仍与程序里的文字一致。
