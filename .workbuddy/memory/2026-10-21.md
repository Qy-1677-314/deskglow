## 修复「文件合集」弹窗 5/6 列抽搐（popup.css 一行）

**现象**：收纳弹窗里拖动过长名字文件后，鼠标移到窗口内某些固定位置时，网格在 5 列和 6 列之间持续抽搐。

**根因（离屏 Electron 测试台实证复现，用用户真实 20 个文件名）**：
1. 弹窗 `.body` 是 `overflow-y: auto` + 经典 8px 滚动条。滚动条出现/消失会把网格宽度改变 8px（624.7 ↔ 616.7），而 `repeat(auto-fill, minmax(100px, 1fr))` 的 6 列恰需 620px——**滚动条就是 5/6 列的开关**。
2. `fit()` 把内容高钳在 420 + 固定 82px chrome，用户真实数据下窗口恒为 544（clientH=453）。此时 5 列内容 426（scrollH 453 == clientH 453，不溢出→无滚动条→网格变宽→6 列），6 列内容 439（scrollH 465 > 453，溢出→出滚动条→网格变窄→5 列）——**两个状态互触发，形成极限环**。
3. 长名字是关键：2 行名的格子更高，移动它改变行的组合，使 5/6 列的内容总高**非单调**（5 列 426 < 6 列 439），系统才能落进振荡区；短名文件的行高一致，不会触发。
4. 鼠标位置相关的原因：悬停格子触发 `:hover` 样式重算 + `.cell` 上 150ms transform 过渡的连续重绘，把待处理的 layout 不断冲刷出来，振荡才可见；停在 padding/间隙则不触发——所以是「某些固定位置」（格子位置）。

**修复**：`src/renderer/popup.css` 的 `.body` 增加 `scrollbar-gutter: stable`——滚动条槽位常驻，网格宽度与滚动条解耦，列数变成窗口宽的纯函数，反馈环从根上断掉。未动任何冻结文件。

**验证**（测试台加载真实 popup.html/css/js + 复刻 createPopup/popup:fit）：
- 修复前：真实数据 + 悬停各格子 → 每次悬停 1~4 次列数翻转；
- 修复后：长名文件拖到每个位置 + 全格子悬停 + 边缘悬停 → 0 翻转；N=15..40 混合名扫描 0 翻转；分组弹窗（600 宽）0 翻转。
- 修复后收纳弹窗恒定 5 列（616.7 < 620），分组弹窗恒定 5 列；内容不溢出时右侧常驻 8px 槽位（视觉上网格窄 8px，可接受）。

**测试台方法**（可复现）：Electron 以「应用目录 + package.json」启动（直接传 .js 会退化成纯 Node 模式；需 `env -u ELECTRON_RUN_AS_NODE`；GPU 崩时加 `--no-sandbox --disable-gpu-shader-disk-cache`）；`require('electron')` 需要 node_modules 可达（临时 junction）。

## 小组件重构为「元素系统」（v1.5.0）

把 v1.4.0 的固定三行面板整块换成「一块透明画布 + 任意多个独立元素」。落地方式与踩过的坑：

### 结构
- 画布：`createWidget()` 建覆盖工作区的透明无边框窗口，平时 `setIgnoreMouseEvents(true,{forward:true})` 整层穿透，编辑态才接管鼠标并 `alwaysOnTop('floating')`；编辑时自动隐藏控制面板，退出还原。
- 层级：仍只调 `zorder.sink()`（1.5s 低频）；`zorder.js` / `zorder.ps1` / Dock 全部未动。
- 元素模型：`store.widgets.elements[]`，字段 `id/type/name/x/y/rot/data/text{size,color,weight,italic,underline,spacing,lineHeight,shadow}/box{bg,radius,shadow,w,h}`；`normalizeElement` 深合并兜默认值，改动用 `setPath` 按路径打补丁。
- 格式化引擎 `src/renderer/widget-fmt.js`：主进程与渲染进程共用（`require` + `<script>` 双通道），含农历表 1900–2100、24 节气、公历/农历/「第几个星期几」三类节日、时区（`Intl` + `formatToParts`）、12 小时制自动补 AM/PM；格式串 `[方括号]` 转义不参与分词。
- 资源：`src/main/dsk.js` 管 `userData/fonts|images` 与 `.dskset` 导入导出（base64 内嵌，单文件 ≤8MB、合计 ≤32MB，替换/追加两种模式）；渲染层走自定义 `dgfile://` 协议，只映射这两个目录且路径必须落在目录内。
- 本机字体：`src/main/fonts.js` 纯 Node 解析 TTF/OTF `name` 表（优先 16 号排版家族名，兼容 `ttcf`），324 个面约 180ms，缓存 10 分钟。本机安全策略会拦 `Add-Type`，所以没有走 .NET 那条路。

### 踩过的坑
- 迁移不生效：`deepMerge` 会用默认值填满 `widgets.elements`，迁移必须读**磁盘上的** `loaded.widgets.elements` 判断是否为空，否则永远认为「已经有元素了」。
- 加了 v4 迁移却忘了把 `DEFAULTS.schema` 从 3 改到 4，会反复迁移。
- `writeAsset` 早先版本在 `asset.name` 已带扩展名时会拼出畸形文件名 —— 改成先拆 base/ext 再重组。
- 重叠式电量：最初直接把数字盖在白色填充上，看不清 —— 有数字时填充压到 24% 透明 + 底部 3.6px 电量条。
- 画布顶栏在 1180px 测试窗口里溢出、六个对齐图标画成虚线框看不出含义 —— 缩短提示、图标改实心条 + 边框参考线，并加「对齐」标签。

### 验证
- 预设往返：导出 788KB（1 字体 + 1 图片）→ 清空本地资源目录 → 导入 replace 还原字体与图片；坏文件被拒绝；越界路径（`../../config.json`）被 `safeName` 规范化后仍落在 `images/` 内。
- 真实配置迁移：schema 3 → 4，`widgets` 只剩 `enabled/elements`，三条元素（时钟/日期/电量）坐标 +16、格式串保留。
- 真实启动：本机有 `.compat`，需 `--no-sandbox`，且必须 `env -u ELECTRON_RUN_AS_NODE -u NODE_OPTIONS` 才是 Electron 模式（否则 `app` 为 undefined）。启动无异常。
- 实测：`--user-data-dir` **改不了** Electron 的 `userData`（仍为 Roaming\DeskGlow），单实例锁会挡掉第二实例；想另开测试实例只能改 package.json 的 name/productName。

## 电量 UI 重做 + 编辑态多选 / 框选 / 吸附（v1.5.0 收尾）

用户反馈「百分比撑出电池外」，顺带要求加自动对齐、`Ctrl` 多选、框选。

### 电量
- 病根：重叠模式的外框宽度写死成 `iconSize * 2.1`，而数字字号由 `text.size` 决定 —— 两者脱钩，字号一大就把数字顶出去。

- 有文字时填充降到 0.32 不透明度（保证白字可读），无文字时实心；文字补一层暗色 `text-shadow`，但用户自己开了文字阴影时不再覆盖。
- 电量条：重叠模式铺满电池宽度（`width:100%`），轨道用 `rgba(barColor, 24)` 跟着主色走，不再是灰紫色。

### 编辑态
- 选中集合从单个 `selectedId` 换成 `selectedIds: Set` + `primaryId`（读数/手柄只认主选中）。
- `Ctrl` 点击切换选中；空白处拖拽框选（`Ctrl` 框选追加）；`Ctrl + A` 全选；多选时不给手柄、对齐按钮切「互相对齐」（对到组包围盒）。

## 电量条与电池本体的对齐（v1.5.0 修正）

- 问题：重叠模式下电量条 `width:100%`，跟着整块 `.bat-inline` 走，右端一直盖到正极凸起底下。
- 改法：把外框几何抽成常量（`BAT_VB 128 / BAT_BODY_X 2 / BAT_BODY_W 116 / BAT_NUB_X 120.5 / BAT_NUB_W 5`），电量条宽 `116/128=90.625%`、左移 `1.5625%`，正好压住身体左右边缘。
- 关键坑：百分比宽必须有稳定参照系。电池和电量条外面套了一层 `.bat-stack`（column flex + `align-items:stretch` + `align-self:stretch`），否则 `.elbody` 在 `al-center / al-right` 下会按 fit-content 收缩，百分比算出来的宽度就对不上了。
- 验证：离屏测量电量条 rect 与 SVG 身体 rect，四个用例（43% / 100% 充电 / 8% 低电 / 80px 字号）左右偏差 ≤0.02px。
- 注意：`preserveAspectRatio="none"` 下 SVG 子元素 `getBoundingClientRect()` 是**变换后**的真实屏幕坐标，可以直接拿来断言，比换算百分比可靠。

## 选中框贴文字墨迹（v1.5.0 续）

- 需求：虚线框不要和文字之间留空，否则不好对齐。
- 实现：`src/renderer/widget.js` 新增 `inkSlack()` / `tightenBox()` —— 用 canvas 的 `actualBoundingBoxAscent/Descent/Left/Right` 量每行文字的**真实墨迹**（多行用逐字符 Range rect 按 top 分组切行），再把 `.elbody` 首/尾子元素的 margin 收成负数，把元素盒削到墨迹上；右侧只在「没手动设宽 + 左对齐」时用 `.elbody{margin-right:-x}` 收（居中/靠右时负 margin 会把文字挤动）。`inset:-3px` 改成 `inset:0`。
- 关键坑：
  1. **必须在元素挂进文档之后再量**。`buildNode` 里调 `tightenBox` 时 root 还没 appendChild，`getBoundingClientRect`/Range 全是 0，静默不生效（表现是 margin 全是空串）。挪到 `render()` 里 `appendChild` 之后。
  2. `Range.getClientRects()` 对文本返回的是**字体盒**（升部+降部）而不是行高盒，所以 `基线 = rect.top + fontBoundingBoxAscent` 是精确的，不需要补半 leading。
  3. 旋转元素量的是轴对齐包围盒 —— 先把 `transform` 临时置 none，量完立刻还原（同一任务内不闪）。
  4. 手动设过 `el.w/el.h` 的元素不削（按用户尺寸）；缩放落手时调一次 `tightenBox` 把旧削掉清回去。
  5. 上沿余量钳到 ≥0（墨迹顶出盒子上方时长不出盒子，免得把文字挤动），下沿不钳（descender 该包住就包住，用正的 margin-bottom 把盒子长大）。
- 语义变化：`el.x/el.y` = 元素盒左上 = 框子 = 贴着文字墨迹。老配置里文字会向上贴到框线（46px 时钟约 15px、15px 日期约 3px），框子本身不挪窝；HUD/面板坐标与框子保持一致。
- 本机 **DPR = 1.5**：`capturePage()` 出来的图是 CSS 像素 ×1.5，裁剪区域要乘 DPR，否则看截图会误判成「框子错位」。
- 验证：离屏测 10 个元素（时钟/日期/文本/多行定宽/手动尺寸/内边距12/居中/旋转/电量/图片），框子与墨迹四边缝隙 ≤0.01px；内边距元素缝隙正好 12px；居中对齐文字无位移；手动尺寸元素保持 220×70 不削；电量/图片完全没被碰。

### 画布点击穿透（用户报「隐形窗口遮挡」）
- **结论：不是 DeskGlow 的锅**。用 Python ctypes（`WindowFromPoint`/`GetWindowLongPtr`/`EnumWindows`/toolhelp32）实测：画布 `WS_EX_TRANSPARENT` 一直挂着，全屏命中地图里它从不出现；用户截图那片区域是被**别的窗口**盖着（截图时是那个白色 AI 聊天窗，复测时是 QQ 窗口 433,223–1409,1004）。小组件和 Dock 一样贴桌面层，被普通窗口盖住就点不到 —— 这是设计而非 bug。
- 顺手加固（防患）：画布 `setIgnoreMouseEvents` 去掉 `forward: true`（非编辑态渲染层只用拖拽/缩放/框选的指针事件，不需要 mousemove；纯 WS_EX_TRANSPARENT 最可靠，也免掉鼠标钩子受 UIPI 影响）；新增 `ensureWidgetPassThrough(force)`，在 `placeCanvas` 的 setBounds 后、退出编辑后立刻补，平时借 `sinkWidget` 心跳 5s 低频兜底 —— 防 Windows 窗口操作把穿透属性冲掉。
- 教训：本机 `Add-Type` 和 .NET 编译器都被安全策略拦（编译 .NET 代码一律拒绝，连 heredoc 里提到编译器文件名都会被拦），但 **Python ctypes 调 user32 完全可用**，以后探 Windows 窗口状态（命中测试/窗口样式/进程归属）就走这条路。
